# Contributing

Lirax Gateway is in the design stage and has not selected a license or code contribution terms. Please discuss external code contributions before submitting them.

## Working from a checkout

1. Read `README.md`, `WORK.md`, and the relevant decision records. A task should have enough context in repository files to proceed without a hosting platform account or access to private planning material.
2. Work on a branch, keep changes focused, and update tests and documentation when behavior changes. Once implementation begins, this file will list local build and test commands; CI should run those same commands.
3. Update the work item or linked document with the result and any remaining question. Review the public diff for secrets and private details.
4. Request review through the available Git hosting platform, or share a Git patch when a platform is unavailable. Record any lasting outcome in the repository so it survives a hosting migration.

Technical decisions with lasting impact belong in `docs/decisions/`. A platform issue or pull request can hold discussion, but should not be the only place where a maintainer can find the current conclusion.
